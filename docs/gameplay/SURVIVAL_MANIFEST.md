# TheLull — манифест сборки системного survival
**Решение автора: 21.11.2026. Статус: обязательный проектный контракт для геймплейных решений и переноса в Unreal Engine 5.8.4.**

Этот документ — не общая декларация. Перед каждой новой survival-системой и до правки её Blueprint-трафарета агент проверяет четыре обязательных пункта ниже. Результат работы — **путь игрока в игре и воспроизводимый Blueprint**, а не очередная модель, метрика или набор разрозненных фич. Правила применяются к Codex, Claude, Grok и следующим исполнителям.

## F−1. Первая игровая площадка (решение автора, 21.11.2026)

**TheLull — survival от третьего лица.** Начинаем с Epic Third Person Template (Games → Third Person → Blueprint → Variant None) в UE 5.8.4. Если проект уже существует, сначала проверить его, не создавать второй и не перезаписывать ассеты. Сохраняем штатные Character/Pawn, GameMode, camera, input, locomotion и animation. Манекен служит временным Генри; улучшения камеры и движения — позднее, по результатам игры, включая уроки Hoarbound о коллизиях и видимости персонажа в помещениях. Не строить альтернативный character/controller/camera с нуля. [Epic Third Person Template — выбрать 5.8](https://dev.epicgames.com/documentation/en-us/unreal-engine/third-person-template-in-unreal-engine?application_version=5.8); точные пути и API сверить в установленном редакторе.

**Первая карта — [L_KeyWestBlockout](../blueprints/project/Content/Maps/L_KeyWestBlockout.md)**. Один связный квартал вокруг 727 Fort Street: улицы, небольшое число доступных укрытий, вышка, АЗС, Bahama Village и другие ориентиры. **727 больше не основной shelter**; он остаётся географическим ориентиром/возможным укрытием, не обязательной целью и не точкой spawn. Дополнительно подобрать два подтверждённых зданием/footprint кандидата shelter. Остальное — закрытые наружные blockout-массы без интерьеров, лута или сложной детализации. Не считать вышку и АЗС автоматически shelter.

География опирается на последние работы Claude в Hoarbound: [PR #340](https://github.com/Nolavel/Hoarbound/pull/340), merge `edbcf021`, [документированная реконструкция](https://github.com/Nolavel/Hoarbound/blob/edbcf0218838416a6ca129639a3a99f64527daae/docs/superpowers/specs/2026-11-18-key-west-727-reconstruction-design.md), [городской frame](https://github.com/Nolavel/Hoarbound/blob/edbcf0218838416a6ca129639a3a99f64527daae/data/world/key_west/reality/config/frame.json), [documented buildings](https://github.com/Nolavel/Hoarbound/blob/edbcf0218838416a6ca129639a3a99f64527daae/data/world/key_west/reality/config/documented_buildings.json), [city footprints](https://github.com/Nolavel/Hoarbound/blob/edbcf0218838416a6ca129639a3a99f64527daae/data/world/key_west/reality/config/city_footprints.json), [export manifest](https://github.com/Nolavel/Hoarbound/blob/edbcf0218838416a6ca129639a3a99f64527daae/data/world/key_west/reality/editor_export/manifest.json). Исторический аудит 400×400 м, чанки −8:3 и −7:3 (512 м), состояние города на конец 2025. Lofts at Bahama Village 918 Fort St и Frederick Douglass Community Center 111 Olivia St документированы. Точные ID и координаты вышки/АЗС пока не подтверждены прочитанными данными; не выдумывать, не считать первой попавшейся вышкой First Exit, при необходимости уточнить охват района. Не переносить старую роль 727, Godot-сцены и игровые скрипты целиком.

Сначала PIE: ходьба, камера, масштаб города, улицы и несколько возможных укрытий. После этого на той же карте подключаем F00 clock и дальнейшие зависимости. Технический clock-probe — только явно включаемый тест, не обычный игровой режим. Никакой обязательной пустой TimeLab перед кварталом.

## 1. Начинать с игрового core loop, а не с частной механики или AI-агента

Рабочая грамматика опирается прежде всего на **The Long Dark: Survival Mode**: ограниченное тело + изменяющийся мир + единое время + конечные возможности. Игрок сам строит намерение и несёт цену его изменения.

**Проверяемый цикл TheLull:**
```text
утро: прочесть состояние тела, погоду, запасы и доступные цели
→ выбрать собственное намерение (не приказ агента)
→ подготовиться / оставить что-то на потом
→ выйти из убежища в замёрзший Key West
→ потратить время, тепло, силы и ограниченные ресурсы на поиск/действия
→ с добычей, знанием или неудачей вернуться либо изменить маршрут
→ решить, на что потратить остаток дня (тепло, вода, ремонт, сохранение топлива)
→ пережить ночь (в том числе возможное пробуждение и новый выбор)
→ новое утро: физические и пространственные последствия сохраняются
```
Это **наш проектный loop**, выведенный из причинных связей жанра, а не объявленная точная схема или код Hinterland. Любая механика обязана влиять минимум на ещё одно звено цикла. Протестированный отдельно «метр холода» без следующего выбора игрока не принят. В перспективе — NPC и сюжет, но core не зависит от их готовности.

**Самый первый строительный инвариант:** один authoritative game clock → упорядоченная симуляция мира → тело/убежище/ресурсы → оплачиваемое действие → сохранённое последствие. Реальное течение времени и длительные действия проходят через один путь. Никакого второго времени для сна, работы, печи или погоды.

## 2. Сначала расследовать и сопоставить реальные источники

Для новой или существенно переделываемой связи записать последовательность:
1. **TLD, Survival Mode:** наблюдаемая механика и её связь с другими; источник/версия; [официальное], [сообщество], [вывод], [неизвестно] — различать.
2. **Жанр:** как ту же задачу решают другие survival-игры и почему; искать полезный паттерн, а не имитировать его целиком.
3. **Hoarbound:** что реально реализовано в GitHub `main`, что было только запланировано в Miro и что обнаружили в build/playtest. Не приравнивать код к подтверждённому UX.
4. **Key West → TheLull:** документальный факт города и отдельная гипотеза о его поведении в вымышленной зиме. Улицы, окна, веранды, старый фонд, ветер, ориентиры и 727 меняют выбор игрока; это не канадский лес, украшенный пальмами.

**Иерархия доказательств:** исходник/официальный документ → воспроизводимый опыт → вывод/предположение. Точные закрытые формулы TLD не выдумывать, баланс/ассеты/UI/тексты не копировать. Статус каждого утверждения показывать в карточке. Заимствование архитектуры Hoarbound автоматически запрещено; брать только проверяемую связь и урок.

Параллельно с Blueprint-сборкой продолжать **отдельное исследование жанра и Key West**. Исследование не блокирует уже проверенный строительный шаг и не расползается в новые D-эксперименты без конкретной игровой неопределённости.

## 3. Каждое принятое решение переводить в собираемый Blueprint-трафарет

**Назначение трафарета — исполнимое задание Claude Code, который через подключённый Unreal MCP создаёт и проверяет настоящие ассеты в открытом локальном проекте.** Это не руководство, по которому автор вручную угадывает графы, и не самостоятельная реализация кода. Мост: исследование Codex → точный Markdown-контракт → создание в UE через Claude Code + Unreal MCP → проверка фактического `.uasset`/PIE → обратная связь и backlog → исправленный, согласованный контракт.

**Один Markdown — один реальный UE asset (или один конкретный конфигурационный файл).** Трафареты располагаются в [`docs/blueprints/project/`](../blueprints/project/) — **зеркале структуры открытого Unreal-проекта**: `Content/`, `Config/`, позже другие реально востребованные пути. Для `Content/Survival/Time/BP_SurvivalWorld.md` ожидаемый результат — `<ProjectRoot>/Content/Survival/Time/BP_SurvivalWorld.uasset`, package `/Game/Survival/Time/BP_SurvivalWorld`. Новые этапы дополняют эту же структуру, а не создают параллельные папки вне зеркала. Каталог `docs/blueprints/project/` — **только текстовый mirror**; исходники `.uasset` и настройки `.ini` записываются Claude в настоящий локальный проект, а не в папку с MD. Общие правила: [`docs/blueprints/README.md`](../blueprints/README.md).

В каждом трафарете обязаны быть:
- точный `Package` и `ParentClass`, список зависимостей и конкретный порядок создания в редакторе UE 5.8.4;
- переменные с **UE-типом, единицей, default**, пометкой runtime/config/save и *единственным* authoritative writer;
- функции/события: имена входных и выходных пинов, порядок execution, branch, интерфейсы, события, прерывания и ответственность за расход ресурсов;
- кто читает состояние, что меняет соседняя система, когда оно сохраняется и как безопасно восстанавливается;
- минимальный сценарий проверки в PIE, ожидаемые наблюдаемые результаты, ошибки/негативные проверки и отметка о фактической проверке.

### Жёсткая привязка к документации UE 5.8

- **Редактор проекта фиксирован: UE 5.8.4** (решение автора). Официальная документация Epic публикуется с меткой **UE 5.8** — для патча `5.8.4` не подразумевается отдельная полная справка. Проверять соответствие **именно установленной 5.8.4** в редакторе, а не подменять API более новыми 5.9/UE6.
- [Epic — Unreal Engine 5.8 Documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine), [Blueprints Visual Scripting](https://dev.epicgames.com/documentation/en-us/unreal-engine/blueprints-visual-scripting-in-unreal-engine), [Blueprint API 5.8](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI), [Blueprint Class Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/blueprint-class-assets-in-unreal-engine), [Editor Scripting](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-and-automating-the-unreal-editor), [Automation Tests](https://dev.epicgames.com/documentation/en-us/unreal-engine/automation-test-framework-in-unreal-engine).
- **Обязательная перепроверка для каждого трафарета:** точный класс, тип переменной, название узла и pin, возможность операции через *фактически подключённый* Unreal MCP, корректное создание/сохранение/компиляция. В карточке писать URL Epic (документация 5.8) + результаты локального API/asset inspection. Случай, когда MCP не умеет создать нужный граф, записывать как **BLOCKED: MCP capability**, не выдумывать эквивалент или объявлять задачу собранной. Официальная документация — источник API; **реальный MCP и редактор** проверяют исполнимость.

### Обязательный цикл Codex → Claude Cloud review → Claude Local → обратная связь

[Разграничение ролей](../../CLAUDE.md): Codex готовит трафареты и владеет лабораторией; **Claude Local** строит реальный UE-проект и ведёт backlog; **Claude Cloud** ведёт техническую подготовку, инженерное ревью и отдельную сверку переданных результатов. Проверка собственных assets локальным исполнителем — самопроверка, а не независимое ревью. Cloud не имеет права выдавать статический анализ за PIE или возвращаться в lab как исполнитель. 

Автор подтвердил 21.11.2026: **UE 5.8.4 уже установлен локально; Unreal MCP ещё не настроен, UE-проект ещё не создан.** Это сообщение автора, не результат инспекции редактора.

**Основная текущая задача Claude Cloud — предварительное инженерное ревью трафаретов Codex до передачи Claude Local.** Проверить первоисточники Epic 5.8, классы, типы, пины, связи, владение состоянием, зависимости, совместимость с готовым Third Person Template и предполагаемую исполнимость через MCP (не объявлять неподтверждённые capability проверенными). Для каждого трафарета фиксировать точный SHA, найденные проблемы, обоснованную конкретную правку и итог `REVIEWED` / `NEEDS REVISION` / `LOCAL VERIFICATION REQUIRED`. Codex устраняет замечания до передачи согласованной версии Local. Не ждать появления `.uasset`, чтобы начать это ревью; после сборки возможна дополнительная сверка, но она вторична. Это статическая инженерная приёмка, не Runtime/PIE и не право менять авторский scope.

Локальный этап запускается по поручению автора: Claude Local сам настраивает MCP и создаёт проект Third Person Template (Blueprint, None); далее проверяет сборку. До него подготовительная работа Codex и Cloud продолжается: точные трафареты ближайших зависимостей, география, API, MCP и валидаторы. Отсутствие редактора блокирует фактическую сборку, не подготовку. Лаборатория служит проверкой конкретного игрового вопроса или регрессии; её сведение к обязательному gate каждого Blueprint запрещено. Численный WIP-лимит и сокращение scope F−1 не утверждены. 

1. Claude Local перед работой сверяет **фактический проект на диске** (путь к `.uproject`, версия 5.8.4, существующие `Content`/`Config`, чужие assets), текущую ветку и список операций **текущего Unreal MCP**. Не выдаёт схематическое дерево за уже существующий проект.
2. Берёт один stencil и его зависимости **с фиксацией Git commit SHA**, устанавливает реальные пути пакетов, валидирует UE 5.8 и поддержку всех нужных действий MCP. При конфликтах либо недоступных пинах не импровизирует.
3. Создаёт **один** целевой asset через MCP в открытом редакторе, проверяет переменные, nodes/links, результат Compile и Save. Проводит предусмотренную PIE/automation-проверку; если нет runtime-подтверждения, статус остаётся ниже `PIE tested`.
4. Сравнивает состояние `.uasset` с каждым существенным пунктом stencil, отмечает **expected vs actual**, достоверность API, эффект для соседней системы и связь с core loop. Не меняет MD задним числом, чтобы скрыть расхождение.
5. Claude Local пишет **backlog по результатам сборки и манифесту** в [`docs/blueprints/project/BACKLOG.md`](../blueprints/project/BACKLOG.md) в своей ветке `ue-claudeflow`: ошибка/расхождение, влияние, severity, evidence (asset/log/PIE), конкретная правка, ответственный, статус. Созданные `.uasset` коммитит только в свою ветку; автор решает интеграцию, а корректировки трафаретов приходят отдельным согласованным handoff к владельцу `ue-codex`.
6. Claude Cloud может отдельно проверить переданные assets/выгрузки и logs, фиксируя предел статической проверки; предложения Local и Cloud передаются Codex. После начала сборки новый цикл начинается от **проверенного факта в UE и накопленного backlog**, а не от бесконечного переписывания MD по предположениям. Манифест служит критерием ревью каждого нового ассета и каждого сообщения backlog.

**Перед интеграцией:** проверить существующие `.uasset`, owner состояния, класс/путь/пины, существующие контракты и пересечение с соседними трафаретами. Если источник и реализация расходятся, записать расхождение и его причину; не менять интерфейсы тихо. Компоненты не должны независимо записывать world time. Одно полено, один предмет и одна плата временем — по одному списанию.

Статусы не смешивать: `source verified` → `stencil drafted` → `asset assembled` → `PIE tested` → `human observed`. Один лишь MD-файл не является работающим Blueprint; зеленая Python CI не подтверждает Unreal и тем более интерес игрока.

## 4. Собирать от фундамента и проверять весь цикл, включая смысл выбора

**Порядок зависимости, не очередь академических лабораторий:**
`F−1 Third Person + Key West blockout` → `F00 clock/steps` → `F01 climate/shelter/heat` → `F02 body` → `F03 finite items/equipment` → `F04 paid actions/cancellation` → `F05 leave/return/night` → `F06 player feedback/discovery`.
Порядок обоснован тем, что следующее звено должно иметь точный источник времени и состояния; тонкие геймплейные детали подбираются позднее.

**Первый сквозной survival-тест — в одном из выбранных укрытий квартала, не обязательно 727:** холодная комната, негерметичный проём, печь, конечное топливо и доска. Игрок сам выбирает подготовку, расход топлива, другое укрытие или отказ от подготовки; время, ресурсы и тело сохраняют последствия. F−1 проверяет площадку и third person; F00 — только clock; дальнейшие этапы — причинные связи.

Требования к сквозной приёмке: один и тот же clock для вылазки/работы/сна; фиксированный порядок климат→источник тепла→комната→тело→потребности; прерывание без бесплатного результата; конечность ресурсов; корректный Save/Load; сравнение при одинаковом старте; отсутствие скрытого «правильного» выбора. После этого — короткие живые тесты: интерес, считываемость причин и собственное намерение игрока не выводятся из CI.

## Рабочая проверка перед каждым новым коммитом, который касается survival

```text
[ ] Названо конкретное звено core loop и новый выбор игрока.
[ ] Проверены TLD + жанр + фактический Hoarbound + релевантный Key West;
    неизвестное/гипотеза помечены; новое решение не противоречит авторскому.
[ ] Для каждого UE-состояния один writer, известны units/readers/save/load.
[ ] Один asset = один MD в зеркальном `project/Content`; проверены Epic 5.8, installed UE 5.8.4 и способность Unreal MCP создать граф.
[ ] После сборки Claude Local сверил asset с stencil и записал расхождения / улучшения в backlog в своей ветке.
[ ] Сказано, что проверено на уровне источника / Python / UE / человека.
[ ] При изменении API обновлены затронутые трафареты и место интеграции.
```

**Связанные источники истины:** [база TLD](reference/README.md), [F00 исследование и домены](reference/SURVIVAL_FOUNDATION_00_TO_UE.md), [манифест общих правил](../../AGENTS.md), [журнал](../../CHANGELOG.md). Код Hoarbound проверяется по GitHub, production-решения Hoarbound — по Miro, новые решения TheLull — по указанию автора и актуальному `production`. При конфликте остановить тихий перенос и указать разницу. Версия UE закреплена 5.8.4, до лета только Blueprint.
