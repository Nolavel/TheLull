# Промпт для локального Claude Code (первый запуск UE)

Запускать в папке проекта TheLull на Windows. Текст ниже — скопировать целиком в Claude Code.

---

Ты — Claude Code на ноутбуке автора (Windows). Задача на сегодня: поставить UE 5.8.4, настроить кэш,
подключить Unreal MCP, создать проект TheLull и крошечный тест. Отчитываться цифрами.

**Железо (не меняется):** HP 15s-du0xxx, **4 ГБ RAM**, Intel HD 620 (видеопамять из тех же 4 ГБ),
на `C:` около 20 ГБ свободно, внешний HDD USB 3.0 на 500 ГБ. Это слабая машина: цель вечера — чтобы
редактор открылся и им можно было пользоваться, а не производительность.

## Правила

1. Сначала прочитай `AGENTS.md`, `CLAUDE.md` и `docs/setup/LOCAL_UE.md` в этом репозитории. Они главнее
   этого промпта. Если расходятся — спроси автора.
2. Ветка: `git checkout ue-claudeflow && git pull`. Инструкция `LOCAL_UE.md` есть только в ней.
   Коммитить и пушить в `ue-claudeflow` можно самому. PR, merge в `production`, чужие ветки — только с
   разрешения автора.
3. **Ничего не удаляй** без спроса: ни папок кэша, ни переменных среды, ни файлов. Нашёл лишнее — покажи
   размер и спроси.
4. Общайся по-русски, коротко. «Готово» — только после проверки, и скажи, чем проверил. Что не проверено —
   назови прямо.
5. Перед каждым тяжёлым шагом записывай свободное место на `C:` и после него тоже.

## Шаг 1. Диски

Спроси у автора букву внешнего HDD (не угадывай, в Проводнике это видно). Ниже она `<X>:`.
Предложи закрепить её в «Управлении дисками», чтобы путь не менялся при переподключении.

Запиши для истории: Product Number (`msinfo32`), объём и слоты памяти по **HWiNFO или CPU-Z** (вкладка SPD).
Диспетчеру задач в части слотов не верь. Железо автор **не покупает** — это только запись.

## Шаг 2. Epic Games Launcher

Проверь, не стоит ли он уже. Если нет — поставь (`winget install EpicGames.EpicGamesLauncher` или
установщик с epicgames.com). Launcher сам ставится на `C:`; это нормально, он небольшой.

В Launcher → Settings → **Edit Vault Cache Location** → `<X>:\Epic\VaultCache`.

## Шаг 3. UE 5.8.4 на внешний диск

Устанавливай в `<X>:\Epic\UE_5.8`. В «Options» **снимай всё лишнее**:

- все целевые платформы, кроме Windows (Android, iOS, Linux, консоли);
- **Editor symbols for debugging** (это десятки гигабайт);
- Starter Content и шаблоны, если их можно снять.

Скажи автору размер загрузки до начала и место на `<X>:` после.

## Шаг 4. Кэш (DDC) — на внутреннем диске, до первого запуска редактора

Решение автора: DDC держим на внутреннем диске, потому что он быстрее USB-HDD. **Но на `C:` мало места,
поэтому обязательно с лимитом.**

Порядок (с UE 5.4 локальный DDC хранит Zen, и приоритет такой):
`UE-ZenDataPath` → Local DDC Path (`UE-LocalDataCachePath`) → системный путь по умолчанию.

1. Сначала покажи автору, что уже задано, и **ничего не меняй** до его ответа:
   ```powershell
   [Environment]::GetEnvironmentVariable("UE-ZenDataPath","User")
   [Environment]::GetEnvironmentVariable("UE-ZenDataPath","Machine")
   [Environment]::GetEnvironmentVariable("UE-LocalDataCachePath","User")
   Get-PSDrive C | Select-Object Used,Free
   Test-Path C:\ProgramData\Epic\Zen\Data; Test-Path "$env:LOCALAPPDATA\UnrealEngine\Common\Zen\Data"
   ```
   Если `UE-ZenDataPath` уже задан — он перекроет всё остальное. Не трогай, сообщи автору.
2. Найди в документации Epic («Using Derived Data Cache in Unreal Engine») **как ограничить размер
   локального DDC/Zen**, и предложи автору конкретный лимит в гигабайтах исходя из свободного места
   (ориентир: оставить на `C:` не меньше 8 ГБ свободными). Не выдумывай параметр — сошлись на документацию.
3. Только после согласия автора задай путь и лимит:
   ```powershell
   New-Item -ItemType Directory -Force C:\UE\DDC | Out-Null
   setx UE-LocalDataCachePath "C:\UE\DDC"
   ```
   Перезапусти Launcher и терминал, чтобы переменная подхватилась.
4. **Правило остановки:** если свободное место на `C:` упало ниже 6 ГБ — останови работу, покажи цифры и
   предложи автору перенести DDC на `<X>:` (`setx UE-LocalDataCachePath "<X>:\UE\DDC"`). Сам не переноси.
5. Старые каталоги Zen на `C:` **не удаляй**: только покажи их размер.

## Шаг 5. Проект TheLull

1. Проект создаётся **в этом же клоне репозитория**, рядом с `docs/` и `AGENTS.md`.
2. Unreal → New Project → Games → **Blank**, **Blueprint**, **без Starter Content**,
   Location — папка на уровень выше клона, Name `TheLull`, чтобы файлы легли в клон.
   Если редактор откажется создавать проект в непустой папке — создай рядом в `TheLull_tmp` и перенеси
   содержимое в клон, сказав об этом автору.
3. В `.gitignore` уже исключены `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`. Проверь это
   через `git status` перед коммитом.

## Шаг 6. Выключить всё тяжёлое

Цель — чтобы редактор работал на 4 ГБ RAM и Intel HD 620. Выключай через Project Settings, а заодно
проверь, что это осело в `Config/DefaultEngine.ini` (его мы коммитим).

- **Lumen:** Rendering → Dynamic Global Illumination Method → **None**; Reflection Method → **Screen Space**.
- **Virtual Shadow Maps:** Shadow Map Method → **Shadow Maps**.
- **Nanite:** снять «Support Nanite» / `r.Nanite=0`. На меши Nanite не включать.
- **Тесселяция и Displacement:** выключить (в UE5 это Nanite Displacement / Tessellation — снять поддержку).
- **Ray Tracing / Path Tracing / Hardware Ray Tracing:** выключить, включая «Support Hardware Ray Tracing».
- **Virtual Textures** (Virtual Texture Support, Virtual Texture Lightmaps): выключить.
- **Temporal Super Resolution:** Anti-Aliasing Method → **FXAA** (TSR и даже TAA дороже).
- **Substrate** (если в 5.8 включён по умолчанию): выключить.
- **Плагины:** отключи то, что проекту не нужно (онлайн-подсистемы, AR/VR/OpenXR, Chaos Vehicles,
  примеры контента, редакторы анимации, которые не используем). Не отключай то, без чего редактор не
  стартует; после каждого блока запускай редактор и проверяй лог.
- **Scalability:** Settings → Engine Scalability Settings → **Low**.
  Editor Preferences → «Use Less CPU when in Background» — включить.
- **Компиляция шейдеров съедает RAM.** Найди в документации Epic, как ограничить число воркеров шейдерного
  компилятора, и поставь 2. Параметр не выдумывай — сошлись на документацию и покажи автору строку из лога.
- Если редактор падает с ошибкой D3D12 — запусти с `-dx11`
  (`UnrealEditor.exe <путь>\TheLull.uproject -dx11`) и запиши текст ошибки.

## Шаг 7. Unreal MCP

Источник: документация Epic «Unreal MCP in Unreal Editor» для 5.8. Плагин экспериментальный.

1. Edit → Plugins: включить **Unreal MCP** и **All Toolsets**, перезапустить редактор.
2. В консоли редактора: `ModelContextProtocol.GenerateClientConfig ClaudeCode`.
3. Перезапусти себя (Claude Code) из корня проекта, где создан конфиг. Сервер: `http://127.0.0.1:8000/mcp`.
4. Проверка: ты видишь инструменты MCP, создаёшь на уровне куб и читаешь список акторов.
5. Порт 8000 наружу не открывать, `DefaultBindAddress` не менять. Конфиг MCP перед коммитом проверь:
   личных путей и токенов в репозиторий не класть.

## Шаг 8. Крошечный тест (и только он)

1. `Content/Tests/BP_LogicTest` (Actor), переменная `bIsCold` (Boolean).
2. Граф: `BeginPlay → Branch(bIsCold) → True: Print String "Cold" / False: Print String "Warm"`.
3. Сохрани, закоммить и запушь в `ue-claudeflow`.
4. Сделай скриншот графа и отдай **автору**. Облачному Claude граф не показывай: он разберёт `.uasset`
   вслепую через rust-uasset, и сравнение должно быть честным.

Никаких игровых систем, уровней, ассетов и зависимостей сверх этого.

## Шаг 9. Отчёт автору и запись в CHANGELOG

Назови цифрами:

- свободное место на `C:` до и после установки, после первого открытия проекта, после компиляции шейдеров;
- размер папки DDC и заданный лимит;
- строку `LogZen` / `LogDerivedDataCache` из `Saved/Logs/TheLull.log` — где реально лежит кэш;
- время первого открытия проекта, FPS пустого уровня (`stat fps`), расход RAM из Диспетчера задач;
- работает ли MCP и какие инструменты видны;
- что сделать не удалось и почему.

Короткую запись об этом добавь в `CHANGELOG.md` (формат — в начале файла), без личных путей.

## Если что-то идёт не так

- **Долгое «не отвечает» — не повод завершать UE.** Первая компиляция шейдеров на слабой машине идёт долго.
  Смотри в Диспетчере задач: CPU или диск заняты — ждём; CPU и диск около нуля несколько минут при памяти
  на пределе — вероятно, зависание, и решение о завершении принимает автор. Запиши, на каком шаге.
- Перед запуском редактора закрой браузер и всё лишнее: на 4 ГБ это решающе.
- Упёрся в место на диске, в лицензию, в вход Epic или в недостающий компонент — остановись и спроси.
